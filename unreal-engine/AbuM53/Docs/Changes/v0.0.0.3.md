# v0.0.0.3 — Fast PLY import, stable Details editing and large sequence playback

Date: 2026-10-25 (UTC). Previous: v0.0.0.2.

## Steps and implementation

1. Preserved the user's Earth package and existing test map before testing. Benchmarked the installed v0.0.0.2 importer, package save and fresh-process load separately. The screenshot's long pause was primarily the package save, where reflected byte-array serialization visited each byte.
2. Added a versioned native frame serializer that writes packed points contiguously. Legacy tagged assets remain readable; transaction/duplication paths retain their required behavior. Saving an old asset upgrades its representation.
3. Added fixed-stride binary PLY chunk decoding, truncated-body preflight and cooperative cancellation. Mixed scalar widths, LE/BE input, SH0–3 and the ASCII/list fallback remain supported. Editor decoding runs on a worker with read/bounds/packing progress; failed or canceled reimports preserve the previous asset.
4. Fixed component unregister/register handling during Details edits. Cache hits now require valid point data; temporary editor reconstruction preserves usable cached data, while source/revision changes invalidate it.
5. Added explicit external-storage manifest imports, a retained CPU frame cache up to 8192 MiB, bounded reservations, and separate requested/displayed frame diagnostics. Equal-sized independent PLY frames are not assigned invented point identities or interpolated.
6. Added a bounded GPU source-buffer cache so looping samples reuse uploads. The default is 2048 MiB; this three-frame test uses 3072 MiB. Pending graph uploads and extraction targets keep valid ownership through graph execution. Added upload/hit/eviction/residency CSV counters and exact GPU readback tests.
7. Diagnosed near-camera/off-axis covariance instability using the supplied Skate data. Added clip-depth checks and a bounded perspective derivative without moving the projected mean. Eight analytic GPU cases verify clipping, covariance and orthographic behavior. Strict RHI validation exposed missing copy-source flags in test readback buffers; those flags were corrected before final validation.
8. Prepared byte-identical private copies of all three Skate PLYs and an external manifest. Imported the index, rendered every 3,000,000-splat sample, exercised reverse warm seeks and native playback, then saved/reopened the isolated test level. Selected a clear camera inside the capture rig, with the complete skater and board in view.
9. Hardened the QA harness for Windows CSV writer locks, nested Slate callbacks during saving, and explicit map saving. Added regression tests for these observed harness failures. Failed intermediate reports remain private evidence and are not represented as successful runs.
10. Built Win64 Editor, Development and Shipping packages, installed the candidate with a verified backup, and checked every installed file. Added an explicit guarded replacement option for untagged same-version QA candidates; released tags remain immutable.
11. Updated the plugin metadata, walkthrough, scope/status, test evidence and local project instructions for v0.0.0.3. The completed change is committed and annotated under the four-part version workflow; no external Git push is performed.

## Files, limitations and migration

Affected areas: `Core` PLY/SPZ cancellation and portable tests; runtime asset version/serialization/import/component files and regression tests; editor factory progress/cancellation; renderer source-cache/projection/readback code and shaders; sequence preparation and UE QA tools; deployment/version metadata; documentation and sanitized evidence.

Use [the walkthrough](../Import_Editing_and_PLY_Sequence_Walkthrough.md) for import, editing, memory settings and sequence preparation. The persistent `abu_M53_Test_01` project has a local v0.0.0.3 test guide and an isolated Skate level. Existing user maps are preserved.

The final local level is `/Game/AbuM53SkateQA/Run_20261025T192728_578606Z/SkateSequenceQA`. The project guide is `AbuM53_v0.0.0.3_Test_Walkthrough.md`. Its project-only GPU source budget is 3072 MiB, with the previous configuration preserved outside Git. The source-space viewing camera is `(0, -0.9, 2)` looking at `(0, -0.8, 0)`, horizontal FOV 90 degrees; the right/down/forward coordinate convention is an explicit viewing assumption.

- Keep a backup before upgrading legacy assets. Older plugin versions cannot read the new native frame representation. The first legacy load is still slow.
- Skate timing is an explicit 30 FPS assumption; the supplied files contain three independent samples and no stable IDs. Native analytic/neural 4D models and arbitrary training checkpoints remain unsupported.
- Both CPU and GPU caches are set to 3072 MiB for this test. Temporary decoding, staging, sorting, tile buffers and other engine allocations use additional memory. Source uploads retain the full stored frame even when the visible-point budget is lower.
- Cold seeks can invalidate an in-flight prefetch and decode that next frame again. Warm retention was verified; further cold-request coalescing remains optimization work.
- External files must remain available and are not automatically included in cooked packages. The per-frame signed array-length limit and whole-asset embedded import budget remain in force.
- Clip-depth rejection uses Gaussian centers; intersecting-volume integration, strict source-renderer conformance, large-scene spatial LOD/streaming, compact layouts, dedicated Sequencer/MRQ support and AMD/Intel qualification remain in [the roadmap](../ImplementationStatus.md).
- Original code/dependency notices are preserved. No private datasets, engine code or engine binaries are added to Git. Existing public-distribution review requirements remain unchanged.
